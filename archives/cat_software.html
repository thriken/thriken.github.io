py2htmlblog：把 Markdown 变成博客，就这么简单

这是什么

py2htmlblog 是一个 Python 写的静态博客生成器。给它 Markdown 文章、分类信息和一个 HTML 模板，它就能生成一个完整的静态网站，丢到任何地方都能跑——GitHub Pages、虚拟主机、对象存储，甚至 U 盘。

它模仿了老牌博客工具 ThingamaBlog 的设计理念（模板 + 数据 = 静态页面），但用 Python 重写，去掉了对 Java 的依赖，并加入了现代博客需要的所有功能。

能做什么

  • 写文章：用 Markdown 写，带 frontmatter 元数据。格式简洁，任何编辑器都能打开
  • 自动构建：一键生成完整的静态站点，首页、归档、分类、文章页、RSS、sitemap 全搞定
  • 多套模板：内置 19 套主题模板，包括从 WordPress 移植的 iNove 经典主题和 17 套 ThingamaBlog 原装模板
  • URL 兼容：生成的 URL 与 ThingamaBlog 完全一致（archives/2014/03/entry_1.html），迁移老博客不会丢搜索引擎索引
  • 多种发布方式：FTP、SFTP、Git 推送，一条命令部署到任何地方
  • GUI 界面：PyQt 写的桌面编辑器，实时 Markdown 预览，不用碰命令行也能写博客
  • ZIP 模板包：模板可以打包成 ZIP，系统自动加载，方便分发和分享

为什么又造一个轮子

ThingamaBlog 是个很好的工具，但它依赖 Java 运行环境，模板语法也相对封闭。当博客从 Windows 迁移到 GitHub Pages 后，每次更新都要手动编辑 HTML，很不方便。

py2htmlblog 的目标就是：保留 ThingamaBlog 的优点（模板分离、静态生成、URL 稳定），同时用 Python 让它更轻便、更开放、更现代化。

技术栈

模板引擎 自研（类似 Jinja2 语法）
Markdown 自研解析器（支持中文）
GUI PyQt5
部署 FTP / SFTP / Git

py2htmlblog 使用指南

2026-07-22

py2htmlblog 使用指南

从安装到写文章、构建、切换主题的完整流程。

1. 环境要求

  • Python 3.7+
  • （可选）PyQt5 — 用于 GUI 界面：pip install PyQt5
  • （可选）paramiko — 用于 SFTP 发布：pip install paramiko

2. 初始化站点

python main.py init "我的博客" "https://example.com" "作者名"

这会在 data/ 下创建 info.json、category.json、links.json 三个配置文件，并在 templates/default/ 下复制默认模板。

3. 配置站点

编辑 data/info.json，设置站点基本信息：

{
  "site_name": "我的博客",
  "tagline": "记录生活与技术",
  "description": "一个有趣的个人博客",
  "site_url": "https://example.com",
  "author": "作者名",
  "language": "zh-CN",
  "timezone": "Asia/Shanghai",
  "template": "default",
  "posts_per_page": 10,
  "rss_count": 20,
  "copyright": "Copyright 2026",
  "nav_pages": [
    {"title": "首页", "url": "index.html"},
    {"title": "归档", "url": "archives.html"}
  ]
}

详细配置项见：data/info.json 字段说明

4. 管理分类

# 添加分类
python main.py add cat "日志" --slug log
python main.py add cat "技术" --slug tech
python main.py add cat "生活" --slug life

# 查看分类
python main.py list cats

# 删除分类（用 ID）
python main.py del cat 2

5. 写文章

方式一：命令行新建

python main.py new "我的第一篇文章" --cat log --tags "博客,Python"

然后输入文章正文（Markdown），输入 EOF 结束。

或者从文件导入正文：

python main.py new "文章标题" --cat tech --file article.md

方式二：mdblog 批量发布

把写好的 Markdown 文件放到 mdblog/ 目录，文件格式如下：

---
title: 文章标题
category: tech
tags: python,教程
datetime: 2026-07-22 17:30:00
slug: article-slug
---
正文内容（Markdown）...

然后运行：

python main.py publish

系统会自动分配 ID、生成 slug、保存到 data/post/ 并立即构建站点。

方式三：GUI 编辑器

python main.py gui

使用 PyQt 桌面编辑器，支持 Markdown 实时预览、分类管理、文章管理。

文章 frontmatter 完整字段

---
id: 1
title: 域名和空间
datetime: 2014-03-15 09:15:08
slug: yu-ming-he-kong-jian
category: log
tags: 域名, 空间
quotes: 几个域名和空间要到期
nearaid: 2
status: published
---
正文内容...
字段 必填 说明
id 否 文章 ID（自动分配时不填）
title 是 文章标题
datetime 否 发布时间，默认当前时间
slug 否 URL 别名，留空自动生成
category 是 分类的 slug
tags 否 标签，逗号分隔
quotes 否 引用/摘要
nearaid 否 关联文章 ID
status 否 published 或 draft

6. 构建站点

python main.py build

构建过程：

站点: 我的博客
模板: default
文章: 10 篇
分类: 3 个
友链: 5 个
正在生成首页...
正在生成归档页...
正在生成分类页...
正在生成文章页...
正在生成月度归档页...
正在生成 RSS...
正在生成 sitemap.xml...
构建完成 → wwwroot/

生成的静态文件在 wwwroot/ 目录中，结构如下：

wwwroot/
├── index.html              # 首页
├── index_2.html            # 第 2 页（如果有多页）
├── archives.html           # 归档/关于页
├── rss.xml                 # RSS 2.0 订阅
├── sitemap.xml             # 搜索引擎站点地图
├── css/                    # 样式表
├── js/                     # 脚本
├── images/                 # 图片
└── archives/               # 归档目录

    ├── cat_tech.html
    ├── 2014/03/entry_1.html # 文章页
    ├── 03-01-2014_03-31-2014.html  # 月度归档
    └── ...

7. 切换主题

在 data/info.json 中修改 template 字段：

{
  "template": "inove"
}

支持的模板名：default、inove、boxed、clean、georgiablue、gettysburg、lovingrey、macstripe、matrixcode、modernlines、orangepurple、plainblue、plainjane、rusty、slashdotclassic、titaniumgold、tpthin、trendy

主题支持 ZIP 压缩包形式，详见 ZIP 模板说明。

8. 发布站点

py2htmlblog 内置三种发布方式，配置一次之后一键部署。

方式一：FTP 上传

适合虚拟主机（如 Bluehost、HostGator 等）。

在 data/info.json 中添加：

"deploy": {
  "method": "ftp",
  "ftp": {
    "host": "ftp.example.com",
    "port": 21,
    "user": "username",
    "password": "your-password",
    "remote_dir": "/public_html/"
  }
}

运行：

python main.py deploy

方式二：SFTP 上传

适合 VPS 或云服务器。

"deploy": {
  "method": "sftp",
  "sftp": {
    "host": "123.45.67.89",
    "port": 22,
    "user": "root",
    "key_file": "~/.ssh/id_rsa",
    "remote_dir": "/var/www/html/"
  }
}

支持密码和密钥两种认证方式。如果使用密钥，设置 key_file 即可，留空 password。

方式三：Git 推送

适合 GitHub Pages、Gitee Pages、Coding Pages 等。

"deploy": {
  "method": "git",
  "git": {
    "remote": "origin",
    "branch": "main",
    "repo_dir": "D:/my-site-repo",
    "commit_message": "Site update"
  }
}

repo_dir 是你本地 Git 仓库的路径。发布时系统会：

  1. 清空仓库目录（保留 .git）
  2. 复制 wwwroot 文件进去
  3. 执行 git add -A && git commit && git push

模拟运行

不确定配置是否正确？先模拟运行看看会上传哪些文件：

python main.py deploy --dry-run

9. 其他命令

# 查看站点信息
python main.py info

# 修改站点信息
python main.py set site_name "新名称"
python main.py set posts_per_page 5

# 列出文章
python main.py list posts

# 管理友链
python main.py add link "GitHub" "https://github.com" --desc "代码托管"
python main.py del link 2
python main.py list links

# 删除文章
python main.py del post 5

py2htmlblog 发布与部署指南

2026-07-22

py2htmlblog 发布与部署指南

从构建到上线：三种发布方式的详细配置与最佳实践。

概述

py2htmlblog 执行 python main.py build 后，静态站点生成在 wwwroot/ 目录中。将 wwwroot/ 部署到线上有三种内置方式：

方式 适用场景 传输协议 需要安装
FTP 虚拟主机、cPanel 空间 FTP 无（Python 内置）
SFTP VPS、云服务器 SSH File Transfer pip install paramiko
Git GitHub Pages、Gitee Pages Git 无（需安装 Git）

配置写在 data/info.json 的 deploy 字段中，一次配置，一键部署。

FTP 发布

适用场景

  • 传统的 PHP 虚拟主机（Bluehost、HostGator、阿里云虚拟主机等）
  • 通过 cPanel / DirectAdmin 管理的空间
  • 任何支持 FTP 上传的托管服务

配置

在 data/info.json 中添加：

{
  "deploy": {
    "method": "ftp",
    "ftp": {
      "host": "ftp.yourdomain.com",
      "port": 21,
      "user": "ftp_username",
      "password": "your-ftp-password",
      "remote_dir": "/public_html/"
    }
  }
}
参数 说明
host FTP 服务器地址
port FTP 端口，默认 21
user FTP 用户名
password FTP 密码
remote_dir 远程上传目录。虚拟主机一般是 /public_html/ 或 /htdocs/

发布

# 先构建
python main.py build

# 发布到 FTP
python main.py deploy

工作流程

  1. 连接 FTP 服务器
  2. 自动创建远程目录结构
  3. 逐个上传 wwwroot 下所有文件
  4. 显示上传进度和结果

注意事项

  • FTP 密码明文存储在 info.json 中，建议将此文件加入 .gitignore
  • 如果虚拟主机支持 SFTP，优先使用 SFTP（加密传输）
  • 某些虚拟主机的 remote_dir 可能是 / 或 ./，按需调整

SFTP 发布

适用场景

  • VPS（阿里云 ECS、腾讯云 CVM、AWS EC2 等）
  • 云服务器（DigitalOcean、Linode、Vultr 等）
  • 任何支持 SSH 登录的 Linux 服务器

安装依赖

pip install paramiko

配置

密码认证

{
  "deploy": {
    "method": "sftp",
    "sftp": {
      "host": "123.45.67.89",
      "port": 22,
      "user": "root",
      "password": "your-password",
      "remote_dir": "/var/www/html/"
    }
  }
}

SSH 密钥认证（推荐）

{
  "deploy": {
    "method": "sftp",
    "sftp": {
      "host": "123.45.67.89",
      "port": 22,
      "user": "root",
      "key_file": "~/.ssh/id_rsa",
      "remote_dir": "/var/www/html/"
    }
  }
}
参数 说明
host 服务器 IP 或域名
port SSH 端口，默认 22
user SSH 用户名
password 密码（与 key_file 二选一）
key_file SSH 私钥路径（支持 ~ 展开）
remote_dir 远程 Web 目录。常见路径：/var/www/html/、/usr/share/nginx/html/

发布

# 构建 + 发布
python main.py build
python main.py deploy

智能增量上传

SFTP 发布会自动比较文件修改时间，只上传有变化的文件，跳过未修改的文件，大幅提升多次发布的速度。

# 第一次发布：全部上传
[1/50] ✓ index.html
[2/50] ✓ archives.html
...

# 第二次发布：只上传变更
[1/50] - index.html (未变化，跳过)
[2/50] ✓ archives.html  ← 这里改了
[3/50] - rss.xml (未变化，跳过)
...

安全建议

  • 优先使用密钥：password 留空，只用 key_file
  • 限制 SSH 用户权限：不要用 root，创建一个只对 Web 目录有写权限的专用用户
  • 文件权限：确保远程目录的所有者与 SSH 用户一致
  # 在服务器上
  sudo chown -R deploy:deploy /var/www/html/

Git 发布

适用场景

  • GitHub Pages — username.github.io 仓库
  • Gitee Pages — Gitee 提供的静态页面服务
  • Coding Pages — 腾讯云开发者平台的静态托管
  • 自建 Git 服务器 — 通过 Git Hooks 自动部署

配置

{
  "deploy": {
    "method": "git",
    "git": {
      "remote": "origin",
      "branch": "main",
      "repo_dir": "D:/projects/my-blog",
      "commit_message": "Site update: {{date}}",
      "sub_dir": ""
    }
  }
}
参数 说明
remote 远程仓库名，默认 origin
branch 推送分支，GitHub Pages 通常为 main 或 gh-pages
repo_dir 本地 Git 仓库的绝对路径
commit_message 提交信息（支持 {{date}} 自动替换为当前日期）
sub_dir 子目录（如有需要在仓库子目录中部署）

GitHub Pages 典型设置

假设你的 GitHub Pages 仓库是 https://github.com/username/username.github.io，已 clone 到本地 D:/projects/username.github.io/：

{
  "deploy": {
    "method": "git",
    "git": {
      "remote": "origin",
      "branch": "main",
      "repo_dir": "D:/projects/username.github.io",
      "commit_message": "Blog update {{date}}"
    }
  }
}

发布流程：

  1. 清空 D:/projects/username.github.io/ 下的旧文件（保留 .git）
  2. 将 wwwroot/ 所有文件复制进去
  3. 执行 git add -A && git commit -m "Blog update 2026-07-22"
  4. 执行 git push origin main
  5. GitHub Actions 自动部署（或直接生效，取决于配置）

Gitee Pages 设置

Gitee Pages 需要手动点击"更新"按钮。推送后记得去 Gitee Pages 设置页触发重新部署。

{
  "deploy": {
    "method": "git",
    "git": {
      "remote": "origin",
      "branch": "master",
      "repo_dir": "D:/projects/gitee-blog",
      "commit_message": "Site update"
    }
  }
}

注意事项

  • repo_dir 必须是已经 clone 好的 Git 仓库
  • 确保本地仓库已正确设置 remote：git remote -v
  • 如果使用 HTTPS 认证，确保已配置 Git 凭据管理器（git config credential.helper）
  • 如果使用 SSH 认证，确保 SSH key 已添加到 GitHub/Gitee

模拟运行

不确定配置是否正确？使用 --dry-run 参数预览：

python main.py deploy --dry-run

输出示例：

FTP → ftp_user@ftp.example.com:21
远程目录: /public_html/
文件数: 25
[模拟运行] 不会实际上传

  [DRY-RUN] index.html
  [DRY-RUN] archives.html
  [DRY-RUN] rss.xml
  [DRY-RUN] sitemap.xml
  [DRY-RUN] css/style.css
  [DRY-RUN] archives/cat_log.html
  ...

一键构建 + 发布

构建和发布是两个步骤，但可以合并为一条命令：

python main.py build && python main.py deploy

或通过 publish 命令（它会先处理 mdblog 再构建，但不包含 deploy）：

python main.py publish && python main.py deploy

如果需要更自动化的流程，可以写一个简单的脚本：

Windows (build-and-deploy.bat):

@echo off
python main.py build
if %errorlevel% equ 0 (
    python main.py deploy
) else (
    echo 构建失败，取消发布
)

Linux/Mac (build-and-deploy.sh):

#!/bin/bash
python main.py build && python main.py deploy

常见问题

Q: FTP 上传失败："550 Permission denied"

A: 检查 remotedir 路径是否正确。虚拟主机通常不允许写入根目录，确保路径指向 publichtml 或 htdocs。

Q: SFTP 连接超时

A: 检查服务器防火墙是否开放了 SSH 端口（默认 22）。如果服务器换了 SSH 端口，修改 port 参数。

Q: Git push 失败："Permission denied (publickey)"

A: SSH 密钥未配置或未添加到 GitHub/Gitee。检查：

ssh -T git@github.com   # 测试 GitHub 连接

如果失败，重新生成并添加 SSH 密钥。

Q: 为什么 Git 发布要清空仓库？

A: 确保仓库中的文件与 wwwroot 完全同步，避免残留删除的文章页面。如果你有需要在仓库中保留的文件，可以使用 sub_dir 参数将博客部署到子目录。

Q: 可以同时配置多个发布方式吗？

A: 每次只能使用一种。如果需要切换，修改 deploy.method 的值即可。所有子配置（ftp/sftp/git）可以同时填写，系统只读取当前 method 对应的配置。

Q: 上传时会覆盖远程已有文件吗？

A: 会。FTP 和 Git 是全量同步。SFTP 会对比修改时间，只上传变更的文件。
